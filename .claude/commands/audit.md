> **注**: 本ファイルは Claude Code 固有の手順。Codex CLI での監査規約正本 = `.claude/audit-standing.md`(モデル非依存・そのまま有効)。

直近の実装を**独立に**監査する。実装側の「テスト通過」報告は合否に使わない。監査は **Tier-1(委譲・機械的・findings only)** と **Tier-2(判定者・薄い裁定+再オーナー化)** に二分する。判定者=CLAUDE.md「役割 = 資源状態 → 割当」表の判定者席(Tier-2 は外部権威への照合に還元済みのため常駐判定者で足りる)。トークン経済の本丸=Tier-1 を判定者から剥がす。

**冒頭ゲート(必ず最初に)**: `npm run check:forbidden` を実行(未コミット差分。コミット済み範囲は `-- --diff <ref>`。正本 = `scripts/checks/forbidden-files.mjs`)。**未監査の `review.*`/`docs/` 変更**の検出は赤旗。独立監査・再オーナー化を強制する(実装者が受け入れ基準を書いて循環させない=要石)。

## 順序の鉄則(2026-07-15 追加・これを破ると監査が二重に走る)

1. **判定者の一次査読と外科的修正を先に終える。**
2. **ツリーを凍結してから Tier-1 を1回だけ委譲する。**
3. 委譲後は**ツリーを触らない**(赤旗が出たら直して**再委譲**=そこで初めて2回目)。

> **動く標的を監査させない**。実例(2026-07-15 D&D ラウンド): 一次査読前に委譲 → 途中で判定者が欠陥を見つけて修正 → 監査者へ追記メッセージ → さらに赤旗 → 修正 → **再監査**。1つの diff に監査が2回(226k + 214k トークン / 34分)走った。凍結してから1回投げれば足りた。

**委譲中は `TaskOutput` でポーリングしない**。返るのは subagent の**生 JSONL トランスクリプト**で、判定者の希少コンテキストを1回あたり万単位で焼く(2026-07-15 のモバイル UI ラウンドだけで4回叩き ≒ 数万トークンを無駄にした)。完了は**自動通知で戻ってくる**。待つ間は「自分の実機確認」「ステージ対象の確定」など**ツリーを変えない**作業だけをする。

**監査者はツリーを一時ミューテートする**(red 証明のため)。**完了後・commit 前に必ずバイト状態を再確認する**——監査中に走らせた `grep` がサボタージュ窓に当たり、実装が壊れて見えた実例がある。

## Tier-1(委譲=別 Codex/Sonnet・契約を変えない)
**実装の文脈を持たない別の冷たいセッション**(別 Codex セッション or `Agent` `model: sonnet`)へ渡す。**外部権威(CR 真理テーブル・判定者作 `review.*`・機械チェック)にアンカー**し、監査者の主観でなく外部真理で叩く。

**ブリーフは常設規約 `.claude/audit-standing.md` を読ませ、タスク固有のことだけ書く**(`AGENTS.md` と実装者ブリーフの関係と同じ)。共通則(findings only・機械チェック `npm run check`・禁止ファイル走査 `npm run check:forbidden`・weakening/vacuity 検査・**到達可能性バー**・**Preview の既知の罠**・報告様式)はそこに一元化済みゆえ**再掲しない**。判定者が毎ラウンド40行の敵対プロンプトを書き下ろすのは委譲漏れ。

ブリーフの型(4行ヘッダ+固有):
```
まず .claude/audit-standing.md を読み、その規約に従って監査せよ。
対象 = <未コミット差分 / 特定コミット>
実装者 = <ChatGPT / Codex / 判定者(自己監査になるので特に厳しく)>
固有の注意 = <スコープ・DEFER・判定者が既に確認済みで再検証不要な項目>
```

委譲先がやること = **`.claude/audit-standing.md` に一元化**(機械チェック・禁止ファイル走査・`review.*` 実行・weakening/vacuity 検査・到達可能性バー・Preview の罠・報告様式)。**ここに再掲しない**(二重管理は必ずドリフトする)。ブリーフで足すのはタスク固有分だけ:

- **CR トラック**: ブリーフ指定の golden が実行可能テストに繋がっているか(**golden 配線確認**)。FP/FN ガード(`review.m66` 等)を巻き込んで壊していないか。`CACHE_SCHEMA_VERSION` の無断変更が無いか。
- **CR トラック**の出力 = `research/cr-grounding/<key>-tier1-findings.md`(各項目 PASS/赤旗 + 根拠)。UI トラック等 CR キーが無いラウンドは**インライン報告でよい**。

## Tier-2(判定者・薄)
1. **まず `docs/judge-protocol.md` を引く**(§1 弁別3問テスト→§6 帰属フローチャート)。findings の**赤旗だけ**読み、`{substrate誤り/compiler誤訳/物差し誤り/曖昧/誤検出}` に帰属裁定。**raw diff を行読みしない**。赤旗ゼロなら設計健全性のみ薄く確認。
   - **finding は鵜呑みにしない。到達可能性を実物で裏取りしてから直す**(`.claude/audit-standing.md` の到達可能性バー)。合成値注入だけの「実証」は却下してよい——ただし**却下の根拠は実測値で示す**(測らずに却下するのも同罪)。実例 = StatusBand のマナ fade MEDIUM は前提が実測で偽ゆえ却下、ref churn は実在ゆえ修正。
2. **再オーナー化**: 草稿 docs(`*.draft`)を独立に CR へ当てて承認し `docs/` へ昇格(commit 前の必須1回)。
3. **実機は要所だけ**: UI に見える変化がある時のみ Claude Preview(`.claude/launch.json` の mtg-onedeck・**コンソールエラー0件**)。ロジックのみは省き `review.*`+CI に委ねる。
4. 分類精度に関わる変更なら `npm run accuracy` の before/after と `review.classifier-corpus` 緑を確認(委譲先に測らせ判定者は数値だけ判定)。
5. 全緑なら `/ship` へ。赤旗があれば実装者に差し戻し(理由明示)、直してから**最初から**再実行。

> 自律ループ中は Tier-1 を必ず委譲する(判定者が機械チェックを自走したら委譲漏れ)。`/autoloop` 参照。
