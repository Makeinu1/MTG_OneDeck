Authority boundary: O4P-09E has local-write authority only. Commit, push,
deploy, publish, and ship are false. The candidate may run focused validation
and preflight, but must not create a checkpoint commit or external write.
Generated engine-API bytes must be current. Because the manifest verifier pins
those bytes to an existing commit, its `lastVerifiedCommit` reanchor and the
resulting fully green `check:docs` are impossible before an authorized semantic
commit; audit current generated bytes now and report only that reanchor as an
unauthorized terminal gate.

1. `online-visibility-intent-v1` is an exact, versioned, prototype-safe union
   of Look, Reveal, and Choose. Unknown fields, accessors, symbols, sparse or
   oversized arrays, duplicate viewers/selections, noncanonical IDs, control
   characters, capability fragments, and client authority fields fail closed.
2. Look accepts only a supported actor-owned/currently-controlled projected
   object or actor-library top count `1..10`, plus an exact active-player
   audience. Reveal accepts the same supported subject with implicit
   all-players audience. Whole zones, another hand/library, unprojected/stale
   handles, hidden indices, and client grant keys fail without mutation.
3. E network grants reject indefinite/manual duration. Wire duration is an
   exact discriminated object; source-bound carries one authorized projected
   public source handle and choice-bound one active projected search-session
   handle. They map exactly to Core
   until-next-command/opening-sequence, until-end-of-turn/current-turn,
   while-source-exists/source-ID, and until-search-completes/session-key.
   Projection emits only the four semantic labels; all values close
   automatically and atomically.
4. Every E top-library grant persists a server-derived Core-only canonical
   digest of the exact top-ID prefix. Object disappearance/incarnation change,
   digest change, shuffle/reorder, player exit, and audience invalidation close
   stale grants even before their declared duration. Rejected commands close
   none, and no projection exposes the digest.
5. Look identities reach only the exact specified players. Reveal reaches all
   active players and changes no zone. A non-viewer participant remains
   concealed/count-only; an observer remains non-authoritative but may mirror
   only the public revealed identity, never private grant metadata. Tests cover
   all three projections explicitly.
6. Choose uses only an active projected search session. The connected seat is
   its selector/decision maker; the Core actor is its rules actor; the exact
   search-session context is required. Actor/seat mismatch is allowed for no
   other payload or context. Existing candidate visibility to the exact rules
   actor and selector is preserved, but no other viewer gains candidates and
   only the selector may submit the result.
7. Core revalidates candidate snapshot, uniqueness, minimum/maximum, actor,
   selector, and decision authority. Because the shipped O4P-01L
   `criteriaKey` is opaque and not executable, every non-empty qualified
   selection fails closed; only an empty qualified selection with
   server-owned `mayFailToFind: true` may complete. The UI keeps unsupported
   qualification in the visible Freeform Manual boundary. Core emits one
   typed private selected-ID result plus projection-safe count; closes the
   session and choice-bound grants; and never accepts an effect, patch, or
   unrelated mutation from the client.
8. Accepted intent, receipt, Core event, persistence, replay, participant/table
   projections, and final digest agree. Exact retries are idempotent; stale,
   reuse mismatch, unauthorized, invalid, and persistence-failure paths leave
   root/journal/revision/grants/sessions/projections unchanged.
9. Validation produces one frozen canonical intent with deterministic field
   and array order. The browser outbox retains that normalized value, and
   `JSON.stringify` bytes for an unacknowledged E intent are identical before
   disconnect and after reconnect resend. No optimistic identity is exposed;
   a refresh projection is validated before the DOM widens, and replay
   reconstructs identical active/closed visibility state.
10. Secret leak 0: public transport, projections, DOM, console, errors, fixtures, screenshots,
    and evidence omit grant/source Core keys, decision-authority records,
    unrelated candidates, other hidden identities/orders, room/invite/
    capability material, and raw private errors.
11. The post-Pregame production path remains rooted in the existing
    `GameScreen` and renders a typed `OnlineVisibilityDecisions` panel with
    Japanese Look/Reveal/Choose flows, confirmation summaries, projected-only
    candidates, 44px controls, keyboard alternatives, busy/offline gating, and
    bounded recovery. No optimistic/Core client mutation exists.
12. D's legacy Look/Reveal/Choose intent members still fail closed and its UI
    points to E. Unsupported compound semantics remain visibly Freeform Manual
    without hidden data. No second game screen, board, hand, stack, reducer, or
    O4P-09F-J behavior is added.
13. Ordinary tests cover 2p/4p Core/application/runtime/replay journeys; all
    duration and invalidation modes; private/public audience matrices;

    reconnect/outbox; persistence reconstruction; UI flows; and Solo/D
