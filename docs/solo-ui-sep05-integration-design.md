# 9/5一人回しUIの現行卓への合流設計

2026-09-13。参照 `e0c98b4`。実装先 `/private/tmp/onedeck-solo-cockpit`、開始HEAD `203e44e`。既存の未コミット作業を保持する。

## Goal

カードを読む、初手を決める、土地とマナを使う、唱える、盤面を見直して解決する行程を、9/5の空間配置と入力の文法で遊べるようにする。現在の検索・選択・支払い・戦闘の作業面を、この卓から開いて戻れる形で接続する。

## Non-goals / What stays untouched

旧storeへの巻戻し、第二のエンジン、新しい保存形式、protocol変更、未対応ルールの自動化、公開は行わない。CockpitClientと既存サーバー操作を確定経路とし、UIは確定済み状態の表示と未確定の選択を担当する。多人数の席・権限・非公開投影を保持する。

## 構図

一人回しのrootから旧構図を上書きしていた `game-screen--cockpit` を外し、9/5から継続する `game.css` の単一adaptive gridを使用する。上端status、中央board、support、必要時decision、hand、下端thumbの順を守る。色別マナ・ターン・フェイズ・ライフをstatusへ集約。下端はUndo/Redo、状況別主操作、次ターン、作業入口、メニューとする。手札展開、複数選択、検索は作業入口からも到達可能にする。

背景は既存AmbientBackdropとDanceFloorLightsを接続し、卓面を透明に戻す。stack/combat/decision/drag/commanderの状態属性をrootへ渡す。共有部品の機能を切らず、soloの構図と多人数の席構図を分ける。

## 行動の優先順位

初手中は専用stageに集中。キープ成功後だけ既存turn.readyを送信して第1メインへ進む。二つは独立したサーバー確定であり、開始が失敗した場合はキープ済みの状態を保ち「ターン開始」から再開できる。再描画・再接続で自動再送しない。

通常時の主操作は、解決中の作業復帰→スタック解決→戦闘の作業復帰→未開始ターンの開始→次フェイズ。自動処理できない効果は既存の手動処理面を使う。複数選択・対象選択中は判断帯に選択と終了の操作を置く。履歴操作とカード操作はbusy/uncertainによる禁止を保持する。

## カード・作業面・演出

既存GameCardのhover/pin、右クリック、ダブルクリック、選択中の操作切替、drag guardを共用する。HandRibbon、LandRow、CommanderAltar、StackBandの連続性を保つ。検索・支払い・戦闘の作業面は閉じる／盤面を見るで未確定入力を消さない。

成功イベントは既存send経路から一度だけ出す。TransitionCue、SemanticPresentationLayer、CommanderRitualLayerを継続し、旧PresentationLayerを追加して重複発火させない。これは9/5との差として意図的に保持する。背景・光は表示専用、状態更新を待たせない。

## 実装順

1. rootとstatus/thumb/decisionの接続、背景の復帰。
2. キープから開始、文脈に応じた主操作。
3. カードと既存作業面の導線、画面サイズ別の到達性。
4. targeted tests、通常入口からのプレイ、画面とconsoleの確認、必要な修正。

## Acceptance criteria

- 初手の確認・配り直し・ボトム選択・キープから第1メインへ到達できる。
- 状態は上端、手札と主操作は下端にあり、説明や空枠が通常卓を占拠しない。
- 土地・マナ・キャスト・解決・Undo/Redoを既存確定経路で行える。
- 検索・複数選択・スタック／戦闘の作業へ到達し、盤面へ戻っても未確定入力を保持できる。
- 375×812、812×375、1440×900でカード・主操作・状態・作業面へ到達でき、console error 0。
- 関連既存テストと型検査／buildを確認。新規検証はキープ後の順序と失敗時の非進行に絞る。

機能のテスト成功を、9/5の全体験の同等性やユーザーの満足の証明には読み替えない。実装・確認結果を本書末尾に追記する。

## 実装・検証結果

- `CockpitTableSurface.tsx`: soloの構図上書きを解除し、status/thumb/decisionと背景・光を接続。色別マナ・ライフは既存sendを使用。キープのreceipt後だけturn.readyを送り、解決／戦闘／フェイズの主操作と作業入口を整理した。
- `DanceFloorLights.tsx`: 実際に読むstateだけを要求する型へ狭め、同じ照明を現在の表示状態で利用。
- `CockpitSessionScreen.tsx`: 背景モーションの設定を既存の音・表示設定へ追加。
- `cockpitSession.css`: soloの小画面を遮っていた非表示指定を多人数用へ限定。作業面と判断帯を小画面へ接続し、見出しとの重なり、背景の透けすぎを修正。
- `CockpitTableSurface.test.tsx`: 既存初手テストへkeep→turn.readyの順序を追加し、keep失敗時に開始しない1件を追加。既存の大量手札、未確定入力の保持、対象選択、他席を見ても自分の手札を保持する検証も通過。

関連5ファイルのテストは合計14件PASS（Surface 7件、MulliganStage / CockpitWorkPanel / cockpitPresentation / cockpitGameState 合計7件）。最初の並列実行では100枚表示のテストが5秒制限に達した。ワーカーを1に制限して検証し、最終Surface実行は7件、テスト時間3.24秒で通過した。テストのアサーションは緩めていない。

型検査、production build、変更TypeScriptのESLint、diffの空白検査を確認。buildは既存の大きいbundleに関する警告あり。リリース用full gateや公開は実施していない。

5183の通常入口と検証用100枚デッキを使用し、次を実操作した。デッキは表示・操作検証用であり、大会適正な構築の証明には用いない。

- 初手→マリガン2回→ボトム選択→キープ→追加操作なしで第1メイン。
- 土地を手札から出す→土地クリックで白マナ→《太陽の指輪》の支払い→盤面を見る→同じ支払案へ復帰→唱える→解決→Undo/Redo。
- 複数選択でカードを選ぶ→判断帯へ選択1枚を表示→選択を終了。
- 同じbrowser sessionで1440×900、375×812、812×375の卓を表示。375ではスタックと解決、812では作業面を確認。作業面の見出しとナビゲーションは修正後に非重複を確認。console error 0。

9/5との差として、確定済みCockpitTableの表示変換、現在の支払・手動解決面、意味イベントの発火元を維持した。旧controllerの自動誘発検出や旧Feedを形式だけ接続して自動対応を装うことはしていない。これらの裁定支援の差と、実際の音の快適さ・全カード・完全試合の品質は、この検証で同等と認定する範囲に含めない。
