# 共通Cockpit：初回完成範囲とプレイ旅程のUX要求

日付: 2026-09-09。状態: 要求を画面と操作へ具体化した仕様案。実機試遊・通信検証・方式採用は未実施。

Goal: 自分のデッキを試し、仲間と始め、複雑な一手を処理し、間違いや切断から戻って試合を終えられる。
Non-goals: この作業での本体実装、アーキテクチャ採用、公開。全カード自動裁定、内蔵通話、スマホ対戦は初回対象外。
Acceptance criteria: 五旅程それぞれの入口、本人と他席の表示、確定、取消、中断、終点を具体化し、未実証と未決を識別できる。
What stays untouched: 既存コード、設定、保存データ、モック、未完了差分。技術選択を本書から確定しない。

要求の正本は[product-requirements](product-requirements.md#要求からの再設計基準)。P番号は同書を参照する。
本書の具体的な表示・操作は要求を満たす提案であり、ユーザーの逐語的な指定ではない。モックの画素値や旧仕様の制約をそのまま必須にしない。

## 1. 初回完成の範囲

| 区分 | 届ける成果 | 完成判定 |
| --- | --- | --- |
| 必須 | PCで一人回し・2人・4人が共通Cockpitを使う | 同じ意味の操作、カード詳細、Stack/Battle、履歴への入口が揃い、各モードの違いが明示される |
| 必須 | 既存一人回しを保全する | 保存デッキと試合を使え、下記§6で保全するマナ・キーワード等の操作支援、試行中のundo/redo、統率者の表示・演出を維持する |
| 必須 | 実デッキで開始から結果まで進む | 読込不備を黙って捨てず、初手、応答、手動処理、戦闘、脱落後の継続を通す |
| 必須 | 会話による対戦を操作で支える | master、HOLD、代行、防御側のブロック確定、複合効果の基本操作を同じ卓で扱う |
| 必須 | 誤操作と一時切断から戻る | ターン内の全体履歴を新しい順に複数回戻し、確定済みか不明な操作を重複させず復帰する |
| 必須 | 必要な情報を必要な相手だけに示す | 私的選択、権限付き閲覧、明示公開が別の行為として成立する |
| 必須 | 無料運用の範囲と保存期限が分かる | 最終利用から6時間の失効期限、制限到達、失効後の次の行動を表示する |
| 希望 | スマホ横画面で一人回し | PC仕様の成立後に同じ旅程を評価。未達をPC公開の失敗へ自動昇格しない |
| 対象外 | スマホ対戦、内蔵音声、任意カードの全自動裁定 | 対応しているような入口や成功表示を作らない |
| 決定した制限 | 脱落・終局は確定後に回復しない | Q-02: 確定前に対象と結果、元に戻せないことを確認し、確定前なら戻れる |
| 決定 | 部屋主が不在masterの操作権を回収できる | Kickとは分離。部屋主不在中は停止し、所有権移譲はしない |

「実デッキ対応」は任意Oracleの自動対応という意味ではない。読み込めるカード、支援範囲、手動で必要になる操作を示す。基本操作でも表現できない必須状況は、注記や口頭処理だけで対応済みに数えない。

一人回しの保存とundoは別に判定する。既存検査では保存からの復元時にundo/redo履歴を消す。保存後にも過去の全履歴を使えることは既存保証ではなく、新要求として勝手に追加しない。

## 2. 全旅程に通すUX規則

| ID | 必要な体験 | 画面と操作の受入条件 |
| --- | --- | --- |
| UX-01 | 次に誰が何をするか分かる | ターンの人、現在の操作担当、判断待ちの相手、接続状態を区別。操作できない場合は理由と次の行動を示す |
| UX-02 | 盤面上の位置を覚えて使える | 通知や他席の選択で自分の盤面・手札を並べ替えない。脱落席を詰めて対象の位置を変えない |
| UX-03 | 読むことと動かすことを往復できる | 詳細閲覧・盤面への最小化・復帰で選択、順番、発生源が残る。詳細を閉じることは効果終了を意味しない |
| UX-04 | 準備と確定を取り違えない | 未確定選択、送信中、確定、結果確認中、拒否を区別。確定前に成功演出をしない |
| UX-05 | 頻出操作に余計な手間がない | tap、1枚draw、数値変更へ一律の確認ダイアログを置かない。複数選択や行き先は必要時だけ開く |
| UX-06 | 大きな影響を実行前に確認できる | 公開、他席への代行、一括移動、脱落・終局では対象と結果を明示。確認だけで回復設計を代用しない |
| UX-07 | 待つ側も卓の状況を追える | 公開発生源と進行/待機状態を示し、秘密の候補や入力途中は送らない。毎操作の通知で会話を埋めない |
| UX-08 | 人が決める範囲が分かる | 自動処理済み、支援で選ぶ部分、手動で行う部分を区別。HOLDをルール上の優先権保証として表示しない |
| UX-09 | 操作方法に依存せず使える | D&D・ダブルクリックにはメニュー代替。キーボードで詳細・選択・確定・取消・復帰でき、フォーカスを見失わない。タッチにhoverや右クリックを必須にしない |
| UX-10 | 結果を追えて、すぐ次を操作できる | 色・音だけで成功や対象を伝えない。演出中も確定状態を参照でき、動きの抑制で意味を失わない |

画面基準はPC 1440×900。375×812と812×375では対戦のPC案内を確認し、横画面一人回しは希望評価を別記する。全サイズで対戦機能を要求する意味ではない。
密度評価にはモックの20/30表示単位を引き継ぐが上限保証ではない。同名で異なる状態のカード、トークン群、装備・オーラ、三人の異なる戦力が見分けられるかを、概要→詳細→元の作業の旅程で検査する。すべての本文を縮小盤面で読ませない。

## 3. 五つの代表旅程

### J-01 — 保存した一人回しから別の手を試す

目的: デッキの理解を深めるため、支援を使いながら試し、戻して比較できる。P-02/03/08/12/14。

準備: 保存済みデッキと試合、統率者、§6で保全する既存マナ支援とキーワード操作を使う。オンライン接続を前提にしない。

1. 保存試合から再開し、デッキ、盤面、手札、支援設定が戻る。保存不能・読込不能時は新規試合で黙って上書きしない。
2. カード詳細で本文を確認し、同じカードから操作へ進む。支援済みの処理を手動で二重適用させない。
3. 選択途中で盤面を確認して戻り、確定する。統率者を使う操作では既存の意味と演出が対応する。
4. undoで直前へ戻し、redoで同じ結果を確認する。別の手を確定した後に以前の未来を誤適用できない。
5. 保存して再開し、確定済み盤面とデッキを確認する。復元後の履歴範囲は画面の可否と一致する。

本人の表示: 現在の試合、使える支援、残る手動処理、戻せる操作。仮想他席の情報は一人回しの既存仕様に従い、オンラインの秘密制限と混同しない。
中断: 未確定選択の取消と、確定盤面のundoを別にする。保存形式が扱えない場合は既存データを保全し、読み込めなかったことを示す。
受入: 保存→支援→別作業への往復→確定→undo/redo→再保存を同じ入口から通せる。ストアの検査だけで画面の保全を認定しない。

### J-02 — 二人が実デッキを持ち寄り、最初の一手を終える

目的: 接続手順を覚える前に、誰が準備中か分かり、実際に遊び始められる。P-01/04/10/11/13。

1. 作成者は部屋を作り、参加者は案内された入口から入る。招待情報は共有操作の対象であり、検証記録には残さない。
2. 各自がデッキを選び、統率者・枚数・読込できない項目を確認する。不備は直す場所を示し、カードを無言で除外しない。
3. 各席の準備状況を共有する。相手にはデッキの私的内容や初手を表示せず、開始できない理由と必要な担当だけを示す。
4. 初手を見てキープ/引き直しを行い、必要な選択を確定する。相手が待つ間も公開情報と自分の詳細を読める。
5. 開始後、draw→土地を置く→呪文を唱える→処理を終えるまで進む。操作担当が誰かを入口から引き継ぐ。

中断: 準備中の再接続では自席の確定済み準備を確認する。未確定の初手選択が失われたなら明示して再選択し、確定済みの引き直しは繰り返さない。
受入: 状態注入なしで二人が同じ開始局面へ進み、最初の処理完了を双方で確認する。失効した入口は「6時間経過等により利用できない」と次の部屋作成/参加導線を示す。部屋の延命として何を最終利用に数えるかは保存設計で明記する。

### J-03 — 応答を受け、複雑な効果を処理して元の進行へ戻る

目的: 一つの判断を細かい画面に分断せず、発生源を見ながら必要な基本操作を連続できる。P-03/04/06/07/08/10。

代表状況: Aの呪文にBが応答し、その後Aがライブラリーから複数枚を探し、必要な公開、異なる行き先への移動、切り直しを手動で行う。個別カードのOracle自動再現を意味しない。

1. Aが対象・支払いを準備して唱える。公開前の候補と公開された呪文を区別する。
2. BがHOLDを要求し、許可された操作担当が応答を確定する。要求中/許可中/返却を双方へ示す。HOLDだけで呪文をStackへ置いたことにしない。
3. 上の応答から処理し、親の発生源へ戻る。各人はStack上の順序、発生源、処理中を追える。
4. 担当が検索・複数選択し、本文確認や盤面へ往復する。必要なカードだけを明示公開し、行き先を分けて移動、切り直しを行う。
5. 相手の判断を待つ場合は待機へ移る。回答の入力代行と、本人が決める権利を区別する。
6. 基本操作の確定後も同じ効果の処理を続け、最後に「処理を終える」。子操作を閉じるだけで親や次の呪文を解決しない。

本人: 発生源、現在の候補、選択群、行き先、実行済み、戻り先。別席の私的領域を扱うときは対象席と権限付き閲覧中を明示する。
他席: 公開発生源、確定した結果、明示公開されたカード、担当/待機。masterに閲覧権限があっても全員公開を意味しない。閲覧者に一度見えた知識をundoで消せたとは表示しない。
代行の境界: 現在の操作者、操作の対象席、選択を決める本人、代行できる確定操作を区別する。masterの閲覧・変更権限だけから、他席のキープ/引き直しや効果で本人に求められる秘密の選択を決める権利は導かない。本人の回答を代行入力する場合も、回答者と操作者を取り違えない表示にする。
受入: 応答→複数基本操作→待機/再開→処理終了→undoを同じ発生源で通す。戻す範囲を表示し、部分処理を完了済みに偽装しない。限定公開は許可されない席へ内容を配送しない。

### J-04 — 四人の戦闘を見渡し、各防御を確定して継続する

目的: 誰が誰へ攻撃し、どの防御が未確定かを、卓を見失わずに判断できる。P-01/05/07/10/12。

代表状況: AがB/Cへ複数の攻撃を宣言し、Bは複数体でブロック、Cは別の防御を選ぶ。Dは応答のため公開局面を参照する。攻撃先の区別が必要なパーマネントも含める。

1. Aは攻撃案を作り、詳細を読んで戻り、攻撃先ごとに確定する。未確定案を他席へ公開しない。
2. B/Cは自分の戦線を詳しく見て、自分の防御を確定する。Dは全戦線の公開状況を追い、他人の防御を編集できない。
3. masterが代行するときは対象の防御席を明示する。本人の確定と競合したら片方を無言で上書きせず、現在の結果と再確認すべき選択を示す。
4. HOLDによる割込み後、同じ戦闘へ戻る。ライフ/ダメージ/移動等を必要な支援または手動で処理し、戦闘を終える。
5. 脱落が発生しても席とカード参照を突然詰めず、残る参加者が次の判断へ進む。脱落者の表示と操作可能範囲を区別する。

受入: B/Cの防御を取り違えず、複数ブロックの関係と未確定の担当が見える。概要から密集した一席の詳細へ進んでも自分の作業を失わない。二人版の成功を四人の証拠にしない。脱落の確定前に対象席と取消不可を確認でき、確定後は訂正できない（Q-02）。

### J-05 — 間違い・切断・終了から状況を理解して次へ進む

目的: 操作の成否が分からないときに二重操作せず、何が残っているかを理解して再開できる。P-08/09/10/11/13。

1. 現在ターン内で複数の操作を確定し、誤ったものまで新しい順にundoする。「自分の最後」ではなく卓全体のどの操作を戻すかを表示する。
2. 効果処理中の操作で応答が途切れる。画面は「結果を確認中」とし、失敗確定や成功の演出を先に出さない。同じ操作の再入力を促さない。
3. 再接続後、確定済みならその結果から、未適用なら未適用と確認できた状態から続ける。拒否なら安全な理由と再選択の入口を示す。
4. 共有された処理担当・発生源・実行済み結果を復元し、必要な人が戻るまでの停止を示す。端末内の未確定選択を復元できない場合は、その部分だけ再選択を案内する。
5. 通常の脱落後継続と勝敗確定を経て結果へ進む。失効予定日時と保存範囲を分かる場所に示す。期限切れデータが戻ったように見せない。

他席: 誰を待っているか、確定済みの公開局面、再開可能かを知れる。エラーや履歴から秘密の候補・認証情報が漏れない。
受入: 保存前の中断と保存後応答喪失を区別する試験で、復帰後の一回の操作が一回だけ反映される。解除済み画面が後から更新・再接続しないことも実通信段階で確認する。

Q-01は2026-09-10に決定: 部屋の作成者を部屋主とし、現在の操作masterとは区別する。

- 部屋主だけが不在masterの操作権を回収できる。対象と新担当を全員へ示し、旧接続の操作権は失効させる。
- Kickは別の管理操作。開始前は参加取消、試合中は退出・脱落を確定する。対象と取消不可を確認し、同じ参加資格での再接続を拒否する。
- 部屋主の一時切断では「部屋主の復帰待ち」として卓を停止する。戻れば現在の確定状態を確認して再開。戻らなければ続行不能で、別の部屋へ移る導線を示す。勝敗を自動確定しない。
- 部屋主のゲーム上の脱落だけでは管理権限を失わない。部屋主所有権の引継ぎは提供しない。
- 最終利用から6時間で部屋失効。通常プレイの受理操作で期限を延長する。部屋主不在中は他席の接続・操作で期限を延長せず、画面に現在の期限を表示する。単なるpingや自動再接続で延命しない。

Q-02は2026-09-10に決定: 誤った脱落・終局も確定後には回復しない。確定画面に対象席・結果と「確定後は元に戻せません」を示し、確定前に戻る操作を用意する。ライフの編集等と脱落・終局の確定を取り違えさせない。通常undoでも確定前へ戻せず、終局後の訂正による再開は提供しない。脱落後の通常継続と一時切断からの復帰は引き続き必要。

## 5. 旅程の検証と実装への引継ぎ

2026-09-10の開発計画に従い、J-01〜05を一人回し→2人→4人の該当段階で検証する。既存モックは入口・選択・往復の参照とし、全旅程のモック完成を実装開始の条件にしない。未接続の体験は必要な段階の共通Cockpitへ接続する。画面の完成と配送・永続化の保証を分け、第二のゲーム実装を作らない。

記録は旅程ごとの「最初の状態、通常操作、本人/他席の見え方、引っ掛かった場所、失った選択、到達した終点、未実装」を残す。秘密や招待情報は残さない。必要なクリック数や戻り操作は観測値として記録し、根拠のない点数で合格を作らない。

各段階で必要な画面状態と遷移を対応付け、途切れる箇所と修正案を具体化する。Q-01の部屋管理とQ-02の取消不可境界は既決事項として実装する。通信未実装をモックで証明しようとせず、その受入を実装段階へ渡す。人間観察の不在は明記し、既にdeferredの工程を新しい必須承認として復活させない。

方式比較を経た現在の順序・受入・担当範囲は[実装計画](cockpit-implementation-plan-2026-09-09.md)を正本とする。次タスクはP0→P1の実装へ進み、全方式比較を繰り返さない。

共有権限・秘密・訂正/復帰について別文脈の読み取り専用レビューを実施し、HIGH/BLOCKERなし。指摘された本人の決定と代行入力の境界をJ-03へ追記した。このレビューはUX試遊や実通信の証拠ではない。


## 6. 初回の操作支援と自動判断の採否（2026-09-10決定）

ユーザーから判断を委任されたため、下記を初回仕様として採用する。採用対象はプレイヤーの操作と成果であり、既存モジュール・エンジン数の維持を指定するものではない。この要求整理では本体を変更していない。次タスクの変更範囲は実装計画に従う。

### 6.1 判断基準と共通化

人が「何をするか」を決め、アプリがその操作の選択・計算・反映・履歴を助ける。マナ生成/支払いの既存支援を残すために必要な本文解析は残す。全般的な効果解釈・誘発検出・置換適用まで連鎖して動かすことは初回の共通Cockpitの既定にしない。

手動だからすべての入力を無条件に受け付けるわけではない。操作権、実在する対象、閲覧範囲、重複送信、確定状態との整合は必ず検査する。任意カードとの相互作用の合法性まで検査済みとは表示しない。解析に失敗してもカードを消したり、自由操作まで封じたりしない。

以下の操作支援は一人回し/2人/4人で共通とする。オンライン専用の簡易操作へ劣化させない。権限・秘密情報・全体undoの範囲はモードに従う。一人回しでは既存のredoも維持するが、対戦に新しいredo要件を加えない。

### 6.3 初回に実状態として扱うもの

個別カード、同名でも異なる状態のトークン、コピー、所有者/コントローラー、付いている対象、カウンター、修整、記録ダメージ、表裏、公開範囲、Stackの発生源/対象、追放カードとの関連を保持する。既存の `engine/types.ts` にあるcontrollerId/faceDown/manualKeywords/attachedTo/LinkedExile等を調査素材として使い、型の存在だけで対応完了とはしない。

コピーは「呪文」「能力」「パーマネントのコピー・トークン」を区別し、コピー元の状態を無条件に全複製しない。必要な特徴を確認して生成する手動支援を初回に含める。特殊なコピー相互作用の自動計算は対象外。

期間・由来・関連先は人が指定できる。自動期限判定がない場合も再開後に参照でき、手動解除できる。自由注記は補助であり、秘密情報やカードの所在を注記だけで代用しない。

この有限な操作集合で代表デッキの処理を完遂することを初回の判定にする。全Oracle/全キーワード対応は約束しない。未知のキーワード専用画面、カードごとの手順wizard、操作履歴を学習して自動化する機構は初回対象外。

### 6.4 確定・取消・復帰

- 未確定の対象/順序/支払い案は取消で破棄できる。確定していない操作に成功演出を出さない。
- 対応する通常の唱える/起動は、選択・計算したコストとStack登録を一つの確定単位として扱う。途中の選択画面を閉じるだけで一部のコストを払わない。
- 別途実行したマナ生成や、手動で明示確定したコストは実行済みとして表示する。後から開いた準備画面を閉じても払い戻さない。訂正には履歴を使い、知識が元に戻るとは表示しない。
- 複数席への一括移動や一括数値反映は一つの確定・履歴単位。複合効果全体は基本操作ごとに確定し、その結果を使って続ける。「処理を終える」前でも実行済み操作を保持する。
- 通常undoは卓全体の新しい順に戻し、戻した状態に対応する発生源・処理段階も復元する。他の人の後続操作を残して一人だけ過去へ戻さない。ターン境界および確定したKick/脱落/終局を越えない。
- 再接続では確定済みの操作と継続中の公開文脈を復元。私的な未確定案を復元できない場合は再選択を案内し、確定済みの支払いを再要求しない。旧保存の復元時に存在しなかった履歴の永続化まで既存保証とはしない。

これは手動卓の操作と履歴の境界であり、任意の不正な唱え方を合法化する裁定ではない。支払いと効果の分離は固定版CR 601.2/602、マナ能力の扱いは605、各キーワードは個別規則を実装時の根拠にする。乱数・秘密を伴う未対応コストを通常の選択案へ偽装せず、手動の明示手順と実行済み記録で扱う。
