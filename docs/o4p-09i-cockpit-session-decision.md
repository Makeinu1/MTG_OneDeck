## Architectural choice

Retain Core, trusted intent binders, projection validation, command identity/receipts, and current storage format conditionally. Replace ownership of asynchronous session lifetime, including HTTP completion, polling, socket setup/recovery, and disposal. Include backend commit-to-delivery behavior in the assessed boundary. Do not wrap the existing controller in a second controller or install a second retry engine.

Implement this ownership change in the existing source path if that can meet the requirements. A new file/version is not itself evidence of better architecture. Existing codecs and socket epoch guards retain value. The alternative of a parallel controller with the same unbounded handshake and backend delivery gaps was rejected. HTTP-only delivery would also need authenticated snapshot/rejoin and presence/lease changes; it is not a free simplification. Framework/full rewrite costs include adapting privacy, receipts, Core semantics, saved sessions, and hosting, without current evidence that those costs solve the observed failures.

Direct review and reproduction found a deeper retained-backend defect: an accepted cast retried with the same identity was rebound against the current board, where its card was no longer in hand, and returned HTTP 400 instead of a duplicate ACK. A changed primitive with an accepted identity also bypassed the intended reuse-mismatch classification. This expands the implementation boundary to the existing repository replay API. Reuse its retained revision-zero checkpoint and journal to reconstruct the accepted operation's prior state for rebinding, then use the current protocol receipt/digest decision. Current authentication still precedes replay; new commands cannot select a historical state. No storage format change, auxiliary intent journal, or new replay engine is justified by this finding. Acceptance requires exact retry without another mutation and rejection of changed input with the same identity.

The same Cockpit uses the existing GameScreen/remote interaction port, a persistent self board, public opponent overview and detail/return, and existing server-bound gameplay controls. Mock mutable state, HOLD ownership, and local undo do not become game authority. Public projection remains a runtime capability; the player surface does not require an extra public-table socket.

## Bounded checks and decision criteria

1. Session checks: delayed HTTP completion after disconnect cannot restart transports or change state/storage; handshake and operation recovery terminate within explicit bounds.
2. Delivery checks: committed variable operations, undo, and manual damage still attempt peer notification if sender ACK fails; repeated accepted identity does not mutate twice.
3. Real local journey: room/deck/Pregame, legal shared actions and convergence, a complete short two-player match, four-player disconnect/recovery with a further accepted operation and all-seat revision/public-digest convergence, and clean browser cleanup. Recovery alone is not continued-play evidence. The full scenario records `revision.afterPostReconnectMutation`: null after the two-player winner, strictly greater than the recovered revision for four players. Ordinary priority/turn authority still applies during absence; this does not promise that any disconnected player's required decision can be bypassed.
4. Cockpit: overview/detail/return without replacing the self board; reachable primary controls at 1440x900; no console errors or cross-audience disclosure. Geometry records the actual enabled/disabled state. A non-actor, eliminated player, or finished match must not gain an enabled action merely to satisfy a geometry check. Legal operation success is established separately by the acting seat's receipt and convergence, not by every seat having an enabled button. Before each viewport measurement, every seat opens the same guided panel through the visible toolbar and scrolls an existing primary control into view. This measures reachability under an explicit UI setup; it is not an assertion that all seats naturally keep a panel open or that the untouched horizontal scroll position exposes every control.

A failure ends that trial, then evidence determines whether the defect belongs to product, driver, or environment. A diagnosed correction permits a new bounded trial. Do not repeat an unchanged unknown failure hoping for green. If retained Core/projection/storage cannot support the representative intent safely, revisit that boundary before extending implementation.

Adoption requires removing the superseded ownership, not leaving a permanent comparison switch. Worktree baseline and selectively adopted preserved changes must be identified in the result. The main production path, exact-SHA CI, Pages, and Worker versions must correspond before production journey evidence is claimed.
