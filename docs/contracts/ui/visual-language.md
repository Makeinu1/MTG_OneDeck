# Visual language

<!-- clause: UI-VIS-001 -->
Cards, zones, stack items, pending choices, warnings, and semantic events use distinct visual roles. Japanese card labels use `printedName ?? name` and are displayed with the established card-name treatment.

<!-- clause: UI-VIS-002 -->
The visual system favors readable hierarchy, stable anchors, restrained decoration, and clear focus. Counters, tapped state, chosen targets, and unresolved decisions remain visible without relying on color alone.

<!-- clause: UI-VIS-003 -->
Spacing, radii, typography, color tokens, and motion values are shared through the existing design system. A new visual token must have one semantic purpose and one documented owner.
