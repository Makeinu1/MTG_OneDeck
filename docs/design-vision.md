## 1. 診断: なぜ現状は 55/100 なのか

ユーザー自己評価 55点(参照系: MTG Arena 74点)。2026-07-08 に実機(デスクトップ1440px・狭幅733px・スマホ縦375px・スマホ横812×375px)で Muldrotha 実デッキを操作し、コード探索(UI全域)と突き合わせて主因を5つに確定した。

### 主因1: モバイル不成立(最大の減点)

- 縦持ちスマホは「横向きにしてください」の壁(`RotateNotice`、`App.css` の `(orientation: portrait) and (max-width: 600px)` で `visibility:hidden`)で**プレイ自体が拒否される**。ゴールドフィッシュの本来の主戦場は「ソファ・通勤・隙間時間のスマホ」であり、その文脈で使えないのは機能欠落と同じ。
- 横持ち(`max-height:480px`)レイアウトも、盤面カード幅 ~40px(判読不能・44pxタッチターゲット未満)、マナステッパー6色分が画面幅を占有、ゲームログ非表示、ゾーンは択一スワップ、と「デスクトップの縮小コピー」の域を出ない。

### 主因2: 操作に迷う(情報アーキテクチャが機械都合)

- **全操作が右クリック/タップメニュー1本道**。基本土地《森》にすら15項目のフラットリスト(タップ/マナ生成/コピー/能力起動/誘発/自動化トグル/裏向き/+1+1カウンター×2/ゾーン移動×5)が同格で並ぶ。エンジンはカード種別・フェーズ・マナを知っているのに、メニューは知らないふりをしている。
- **頻度と面積が逆転**: 最高頻度のフェーズ送りは暗号的ドット「解維引 ●1 戦 2 終」、一方で破壊的操作(最初からやり直す/デッキ選択に戻る)がサイドバーの一等地に大きく常設。
- **「今なにができるか」を UI が答えない**: プレイ可能カードのハイライトなし、マナ支払い可否の事前提示なし。ユーザーは頭の中でマナ計算してから UI に命令する——Arena が自動でやってくれることを全部人間がやる。
- **学習可能性ゼロ**: メニューが全てなのに、メニューの存在を教えるものが何もない(オンボーディング・empty state・ヒントなし)。

### 主因3: 気持ち良さの欠如(Arenaとの19点差の体感的正体)

- ドロー・キャスト・解決・ETB・ダメージ、すべて**無音・無モーションの即時DOM更新**。「ゲームを遊んでいる」でなく「状態管理ツールを操作している」体験。
- 盤面の大半が空黒パネルで視覚的焦点がない。カードが小さく空間が広い。
- 細部の質感が安い: アイコンは Unicode 文字の偽装(`ti ti-*` クラスに実フォントなし)、日本語版画像がないカードは「Localized Image Not Available」プレースホルダがそのまま見える。
- ただし**方向性(黒フェルト+金+Cinzel の「夜のカードテーブル」)自体は独自性のある資産**。問題は品質であって路線ではない。

### 主因4: エンジンが見えない(ユーザーの直感「UIがエンジンに追いついていない」は正しい)

- guided resolution・誘発検出・ルール分類・per-card 自動化という誠実なエンジン(~12,400行)の賢さが、UI上は「チェックボックス2つ+浮動スタックウィジェット+メニューの奥の項目」に埋没。
- 誘発→スタック→解決→結果という**ゲームの物語**が可視化されない。何が自動で起き、何を自分が決めたのかの履歴が薄いログ文字列だけ。
- スタックは盤面中央を覆う半透明の浮動ウィジェットで、機能はあるが誇りがない。

### 主因5: 構造的負債(上記を直せずにいる理由)

- `Playmat.tsx` 1,735行の神コンポーネント: ~25個のダイアログ useState・全メニュー構築・DnD 配線が集中。レスポンシブな再設計の最大障害。
- `App.css` 4,960行に**死んだレイアウト系統が併存**(`:838-960` + media query `:2793-2872` は現JSX未使用。実体は `:3307` 以降の「M4.13 overrides」)。カスケードの汚染源。
- view state(選択・ホバー・ビューア開閉)が store 外のコンポーネントローカルで、画面分割・共有ができない。

**配点感**(55点の内訳): モバイル不成立 −15 / IA混乱 −10 / 気持ち良さ −10 / エンジン不可視 −5 / 学習性 −5。刷新後の目標は **80点**(Arena 74 を「自分のデッキで遊べる」領域で上回る)。

## 2. ビジョン

> **ソファで、縦持ちスマホで、片手で、3分の隙間時間に自分のデッキを回して気持ちよくなれる「ポケットの中の一人回しテーブル」。その設計を正としてデスクトップへ展開する。**

Arena は対戦ゲーム。本作は**自分のデッキとの対話**——回して、確かめて、悦に入る。だから Arena の模倣ではなく、(a) 立ち上がりの速さ (b) 盤面編集の自由(サンドボックス) (c) 自分のデッキが「動いている」ことの誇示、で勝つ。

### 狙う感情 — 理解と発見の快感(北極星②・2026-07-08 追記)

> 本作が届ける快感は「勝利」ではなく**「理解と発見」**である——この初手は強い/このシナジーはちゃんと繋がる/このデッキ、回り始めた/このコンボは美しい。雀魂が麻雀を演出・音・リズムでエンターテインメントへ昇華したように、一人回しを「遊びたくなる体験」へ昇華する。ただし輸入するのは見た目ではなく**演出強弱のリズム設計**: 常時派手にしない。ほとんどの時間は静か(カードと思考が主役)で、デッキが動き出す瞬間だけ一段盛る。この静と動の差が没入を作る。

- **演出強度は段階制**: 静寂(思考中)→ 小反応(ホバー/タップ/土地)→ 明確なアクション(ドロー/キャスト/墓地送り)→ 儀式的アクション(統率者キャスト/スタック解決/攻撃開始)→ 高揚イベント(連鎖・コンボ・大量ドロー)。全操作を同じ強さで演出しない。連続処理時は演出を自動圧縮してテンポを守る。
- **祝祭の優先順位**(高強度を割り当てる順):
  1. **スタックの物語** — 唱える→積む→解決。MTGらしさの中心であり、雀魂のリーチ→ツモ→和了に相当する最重要演出対象。
  2. **統率者の主役登場** — 統率領域から登場する瞬間だけ一段上げる(毎回大げさにしない)。
  3. **連鎖感** — コンボを厳密検出しない。「短時間の複数誘発/1ターン大量ドロー/大量トークン/マナ急増/スタック連続解決」等のヒューリスティックで背景と音を一段だけ盛る=「お、回り始めた」。
  4. **初手・ゲーム開始の儀式** — 7枚が1枚ずつ配られ扇に整う。キープ=「このゲームが始まる」確定の小演出。
- **エンジンの見える化は北極星①の製品価値化**: 誘発→スタック→解決の物語を可視化する原則4はこの星の土台であり、エンジンのイベントストリーム(S-EVENTS/cr-603 系)が連鎖感ヒューリスティックの供給源になる(エンジン背骨とゲームフィールの結合点)。
- 設計材料の出典 = `research/design/vision-sources/game-feel-dialogue-2026-07.txt`(演出レベル別の対象操作リスト・音3レイヤー・イベント別演出・5場面体験モック等の詳細は、D6/D7 契約時にここから蒸留する。契約への全文転写はしない=北極星③)。

### 7原則(すべての D-スライスの判定基準)

1. **Portrait-first** — 縦持ちが第一級市民。回転の壁は撤去。1画面には「今関係あるもの」だけを見せ、残りはシート/フィードに畳む。デスクトップは同じ部品の3カラム展開であり、**別コードパスを作らない**(landscape-fork が腐った教訓)。
2. **「次にすること」駆動** — 画面下の親指ゾーンに常設のプライマリアクションボタン。文脈で「次のフェイズ→」「スタックを解決」「攻撃を確定」等に切り替わり、ゲームのリズムを作る(Arena の青ボタンに相当)。スタック未解決中のフェイズ移動禁止(CLAUDE.md 唯一の強制ルール)はこのボタンの状態遷移に織り込む。
3. **カードシート** — カードをタップ=拡大画像+アクションシート(bottom sheet)。エンジンの文脈(カード種別・フェーズ・マナ・盤面)でランク付けした**上位1〜3アクションを大きく**、全アクション(強行・手動編集含む)は「その他」に畳む。右クリックメニューの後継(デスクトップの右クリックも同じシートを開く)。《森》なら「マナを生成してタップ」が一等地、「+1/+1カウンター」は畳みの中。
4. **エンジンの見える化** — 誘発候補・自動解決・警告・ログを単一の**フィード**(タイムライン)に統合し、右端から展開。スタックは浮動ウィジェットでなく画面上部の帯(タップで展開)。「エンジンが何をしてくれたか」が誇らしく見えることが、このプロジェクトの背骨(CRを検査器にするエンジン)の製品価値化そのもの。
5. **祝祭感は少数精鋭** — モーションはドロー・解決・ETB・ダメージの4種に絞って高品質に(全部を薄く動かさない)。ハプティクス(`navigator.vibrate`)は主要アクションに1発。音はオプトイン。`prefers-reduced-motion` を尊重。*2026-07-08 補記*: この4種は演出強度リズム(§2「狙う感情」)の**最初のスライス(D5)であって終点ではない**。連鎖感・音・セッション演出は D6/D7(vision-only)へ。
6. **サンドボックス哲学の維持** — 警告は出すが止めない。全操作に強行経路と右クリック(シート)代替。review.*・不変条件 I1〜I7・検証プロトコルと共存する(UIの刷新はエンジン契約を変えない)。
7. **カードが主役(クローム予算25%)** — *2026-07-08 Round 2 でユーザーFBにより新設・数値化*。非カードUI(ステータス帯+親指ゾーン+ラベル類)は画面高の25%以下、盤面カード領域(盤面+土地行)は55%以上。常設のゾーンラベル・相手ライフ行・ゾーンチップ列は廃止し「タップで出す」(シート)へ降格。カード上に恒常テキストを重ねない(カード自身が情報)。実測(モックv2・375×812): クローム16%・盤面カード66%(v1は約37%)。

### ビジュアル裁定 — 「アルケイン戦術卓」正式採用(ユーザー裁定 2026-07-08 Round 3)

**旧「夜のカードテーブル」(緑金フェルト)を廃止し、「アルケイン戦術卓 (Arcane Tactical Table)」を正式採用。** 黒〜チャコール〜深ネイビーの卓上に、カード画像とマナ5色だけが意味を持って光る「魔法的な戦術テーブル」。背景は一枚絵でなく、盤面各ゾーンに空間的意味を与える**反応する舞台**(通常は静か・イベント時だけ控えめに反応)。意味色 = 金(行動)/青白(スタックの緊張)/白金(統率者)。トークン正本と StageBackdrop 仕様は `docs/design-system.md` §2・§8。

*裁定の経緯*: Round 2 でモックに A(夜のフェルト深化)/B(ミッドナイト・グラス)の A/Bテーマ切替を実装し体感比較に付した。ユーザーが添付した game-feel 議論(`research/design/vision-sources/game-feel-dialogue-2026-07.txt`)が「フェルトを捨て暗い魔導戦術卓を第一候補に」と推奨し、ユーザーがこれを採択。Round 3 でモックを戦術卓の単一テーマへ確定し、A/B切替は撤去した。

## 3. ラフ設計(情報アーキテクチャ)

### 縦持ち(スマホ・第一級)— v2(2026-07-08 Round 2 改訂)

```
┌─────────────────────────────┐
│ [T5 メイン1 ●●●○][山87 墓4 追1][♥40][🔔2] │ ← ステータス帯1行36px。全てタップでシート
├─────────────────────────────┤
│ 盤面(ラベルなし・カード主役):                  │
│   クリーチャー — 統一サイズ棚(横スク・96px基準)  │
│   ── hairline ──                        │
│   その他パーマネント — 同じ棚規則(BoardShelf)   │
├─────────────────────────────┤
│ 土地行(物理スタック・横スクロール・高さ~96px):   │
│  [統率者🃏][森×3 1⤵][島×2][沼][繁殖池⤵]…   │
├─────────────────────────────┤
│ 手札(横スクロール・プレイ可能カードは金縁発光)     │
│ [↩][ 次のフェイズ →(プライマリ) ][≡]         │ ← 親指ゾーン
└─────────────────────────────┘
フィード(ログ+誘発+警告)= ベル/右端スワイプで展開
相手ライフ・ゾーン一覧・自分ライフ増減 = ステータス帯チップのタップでシート
```

- **盤面=BoardShelf**(2026-07-09 Round 4)**【SUPERSEDED 2026-07-18 → adaptiveLaneLayout。正本=design-system §8 の退役注記】**: クリーチャー/その他とも統一サイズの棚(横スクロール)。枚数で 96→84→72px へ密度縮小・14枚〜は重ね。グリッド列数の切替でなく**カード幅の連続適応**(design-system §8 BoardShelf)。
- **土地=紙EDHの机上再現**(ユーザーFB採用): 同名基本地形は実カードの「ずらし重ね」(上端を数pxずつ見せる)+枚数バッジ「×3」。タップ済みは横倒し(束内は傾き+「1⤵」)。特殊地形は個別カード。行ごと横スクロール。抽象チップ(色別◆)は不採用=カードそのものを見せる。
- **統率者は統率領域にいる間、土地行の左端に金枠カードとして常駐**(高頻度の「唱える」導線+常に見える)。
- **誘発候補**はフィードに乗せつつ、未処理があればベルにバッジ。プライマリアクションが「誘発を処理」に切り替わる。
- **破壊的操作**(やり直す/デッキへ戻る)は ≡ メニューの最深部へ降格。
- **反応する舞台**: 卓中央の楕円の主舞台(光溜まり)+外周の戦術ライン+手前の手札レスト+周辺ヴィネットで「アルケイン戦術卓の上」の空気を作る。通常は静か・イベント時だけ反応(design-system §8 StageBackdrop)。
